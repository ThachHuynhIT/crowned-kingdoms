# CLAUDE.md

Guidance for AI coding assistants working in this repo.

## Project

Crowned Kingdoms (formerly _Chín Vương Miện_ / _Nine Crowns_; repo and package `crowned-kingdoms`) — a kingdom-building roguelite auto-battler: each year draw 3 cards, play 1 onto a 5×5 kingdom board, then watch your army fight a neighbouring king automatically. Phaser 4 + TypeScript (strict) + Vite + Vitest, generated pixel art, Stardew-style UI, web-first. The binding design is `docs/superpowers/specs/2026-10-16-crowned-kingdoms-design.md` (Vietnamese), split into sub-projects G0–G5, each with its own plan in `docs/superpowers/plans/`. Summary docs: `docs/GDD.md`, `docs/ART_STYLE.md`, `docs/ROADMAP.md` (check it before starting a feature).

## Commands

```bash
npm run dev        # Vite dev server :5173
npm test           # Vitest (src/**/*.test.ts)
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
npm run build      # typecheck + production build
```

Run `npm run lint && npm run typecheck && npm test && npm run build` before calling work done. In Git Bash on Windows, run npm/npx with `< /dev/null` or they can hang.

## Architecture rules

- **Layers** (spec §12.1): `src/core` (pure infra: generic `EventBus`, `Rng`/`hashSeed`, `SimClock`, `SpatialHash`, `geom`, `noise`), `src/data` (values and types only; `save.ts` holds the IndexedDB names and the player-facing storage texts), `src/game` (rules: `run/` state (RunState **version 6**: offers + `pendingOffers` queue, decrees, quests, rng streams draw/reward/calendar/council/quest, plus `perk`, `unlockedCards`, `freeMovesUsed`)·board·deck (draw/discard piles, `refillHand`)·playable·rewards·battleSetup·yearFlow·flow (`cardOffer`, `enqueueOffers`, `closeOffer`)·yearEnd·commands·council·decrees·quests·enemyArmy·calendar (`RULES_FULL` = 30 years, 'full' calendar, council + quests + 3 bosses, manual battle start; `RULES_G2` = 15 years, 'short'; `RULES_G1` is the default of `newRun`/`runHeadless`)·income·modifiers·RunController (optional 4th arg `persistence`: with it every command is applied, checkpointed, then announced in FIFO order and `whenIdle()` waits; without it everything stays synchronous; `kickoff()` rebuilds a battle loaded in phase `battle` from tick 0; remembers the chosen battle speed), `cards/` registry (`ALL_KINGS`: nine kings; all nine are playable via `PLAYABLE_KINGS`; each `KingDef` carries three `perks: PerkDef[]`; `NEUTRAL_CARDS` holds the two meta cards `neutral_duplicate` and `neutral_royal_seal`, offered only when unlocked)·describe·`custom/` (handlers for the `custom` effects of cards and thrones; `CUSTOM_FLAG_IDS` lists custom ids read by other code, e.g. battle setup, instead of by a handler), `battle/` types·world·compose·targeting·movement·combat·behaviours·statuses·bosses·structures·intervention (manual + auto-fire boulder)·step·hash·BattleRunner·steering, `save/` (`encodeRun`/`decodeRun` envelope `{formatVersion: 1, version, contentHash, state}` — `decodeRun` never trusts the disk: it validates everything, migrates state 3 → 4 → 5 → 6 (5: the Ngai moves from plot 12 to plot 2; 6: adds `perk`, `unlockedCards`, `freeMovesUsed`), accepts a changed content hash while every id still resolves, and answers ok / empty / incompatible; `SaveCoordinator` = FIFO write queue, an ended run clears the save; `MemorySaveStore`), `meta/` (pure meta-progression, spec §9.1–§9.2: `profile` (`MetaProfile`, `META_SAVE_VERSION = 1`), `crowns` (`settleRun`: Crown Points `round((years + 3×conquered + 5×bosses + 20 if won) × (1 + 0.2 × gai))`, mastery, `runKey` = hash of the ended run), `unlocks` (kings, perks at mastery 10/30/60, neutral cards, Gai 1–5), `codec` (`decodeMeta` repairs every field to its default, never drops the profile)), `sim/` headless + `bots/random` + `bots/scripted`, `testing/fixtures.ts` (+ `bossKit` for boss battles), `events.ts`), `src/platform` (the only code that touches IndexedDB: `storage/idbSaveStore` + `createSaveStore` with a one-way fallback to memory and one warning, `session.ts` `createSession` (also holds and saves the meta profile, which is never cleared); `src/game` must not import it — scenes inject the session through the Phaser registry, see `scenes/sessionRegistry.ts`), `src/render` (generated art + Phaser renderers), `src/ui` (theme, shared widgets, HUD parts, `info/` building/unit info box + `runSummary`, `modals/` reward·conquest·calendar (6×5 for 30 years)·deck·`CouncilModal`·`QuestModal`·`councilModel`, `planning/` hand (4 slots)·calendar strip·scout·`DecreeQuestPanel`, `realm/` layout and calendar model, `battle/battleReadout` (incl. `bossReadout`), `resumeModel`, `kingSelectLayout`), `src/scenes` (Boot (opens the save session and loads the meta profile into it) → Preload → MainMenu (Continue, Crowns) → KingSelect (nine kings with locks, perk and Gai choice) → Realm + PlanningHud/BattleHud → RunEnd (Crown Points tally); `CrownsScene` shows points, mastery and unlocks; `RealmData = { seed, kingId, perk, difficulty } | { resume: RunState }`), `src/audio` is still not created.
- **Events:** `src/core/events.ts` is only the generic `EventBus`; `GameEvents` + `createGameBus` live in `src/game/events.ts` (ESLint forbids core → game imports, so spec §12.5's "core" location does not apply).
- **Headless:** `runHeadless({ seed, kingId: 'wheat' })` in `src/game/sim/headless.ts` plays a whole run with `randomBot` (no Phaser); `determinism.test.ts` and `benchmark.test.ts` in `src/game/battle/` run under `npm test`.
- **Preview:** `.claude/launch.json` defines the `dev` preview config (Vite :5173); `window.game` is exposed for `preview_eval`.
- **`src/game`, `src/data`, `src/core` must not import Phaser or `scenes/render/ui/platform/audio`; `src/data` must not import `src/game`** (ESLint `no-restricted-imports`, spec §12.4). Test files there obey the same rules.
- **Determinism** (spec §8.12): `src/game`, `src/data`, `src/core` never use `Math.random`, `Date.now`, `performance.now`, `Math.hypot/sin/cos/tan/atan2/exp/log/pow` (ESLint `no-restricted-properties`); only `+ − × ÷` and `Math.sqrt/floor/ceil/round/min/max/abs`. Randomness goes through `Rng` (`src/core/random.ts`) seeded per stream with `hashSeed`; the battle uses no `Rng` at all (ties broken by id/plot). Never let `Map`/`Set` iteration order decide a simulation result — sort by id first. Battles advance in `SimClock` fixed ticks (10/s).
- **Board and view (spec `2026-11-06-iso-board-redesign-design.md`):** the Ngai stands on **plot 2** (`THRONE_PLOT`, back row, middle column, against the mountain); the nine middle plots start open and empty. World geometry lives in `src/data/boardGeometry.ts`: 64 px plots, 768 px field, board origin 224, `WALL_Y` 176, buildings centred on their plot, a `DEPLOY_BOX` in front of each door; only our own units pass through our own buildings; one road from the board's south edge. The simulation stays on the square grid; only drawing is isometric 2:1 (`src/core/iso.ts` `project`/`unproject`, mirrored so the enemy comes in from the right of the screen; a plot is a 128×64 diamond at zoom 1). Every input goes through `unproject`; the realm camera (`src/ui/realm/cameraModel.ts`) zooms freely from the phase's overview zoom (`overviewZoom` in `realmLayout.ts`: the board is 65% of a desktop screen's width, 33/32 on phones) up to 3×, pans at any zoom and never centres north of the wall; HUDs read the pixel-snapped view (`snapView`) from the `realm:view` event (spec `2026-11-08-iso-board-polish-design.md`). Enemies come out of the portal `ENEMY_PORTAL` at the south end of the road and kill every unit of ours they can hit before they go for buildings (taunt and the rage excepted). Field decoration (`src/render/decorationModel.ts`, `FIELD_DECOR`) is seeded art only: it never touches the run RNG or the battle. Ground art: river water and sand banks are filled from seamless textures (`GROUND_TEXTURE_FILES`), wild objects only from `DECOR_APPROVED`.
- **Data-driven:** every gameplay number lives in `src/data/*`.
- **External assets:** follow `docs/ASSET_LICENSES.md`; register them in `docs/assets.manifest.yml` (schema: `docs/ASSET_MANIFEST.md`) and `CREDITS.md` before committing. Never download and commit an asset just because a URL was found.
- **Generating images (AI/Codex/imagegen): MANDATORY, every single time, for every agent (Claude, Codex, subagents).** Before generating or requesting any game image (buildings, units, terrain, portraits, icons, card art, walls, UI art), read `docs/ART_STYLE.md` — sections "Quy tắc vẽ" and "Góc nhìn" (Stardew 2.5D, the approved harvester-house reference, the reusable prompt, the pre-approval checklist). Attach the approved reference image `docs/art-review/style-references/harvester-house-front-approved.png` (and an approved image of the same kind where one exists), build the prompt from the "Prompt mẫu dùng lại" block (building prompts: `python docs/art-review/g3e/buildings/make_prompts.py <group>`; `tools/test_art_prompts.py` guards it) and never write a prompt from memory. Every Codex prompt must itself tell Codex to read that document. Try ONE sample of a new kind of asset and get the owner's approval before drawing the whole group; review each group before adopting; log prompts and sources under `docs/art-review/`. Skipping the document is a defect: the owner already rejected two batches drawn from the wrong viewpoint.
- **Saving (spec §9.3):** the run is written (IndexedDB db `crowned-kingdoms` v1, stores `run`/`meta`, key `current`; G3 never touches `meta`) after every successful command outside battle and on battle entry and exit — never per tick, speed change, intervene or the auto-fire toggle. Reload mid-battle restarts the battle from tick 0 with the same setup; an ended run clears the save. Bumping `RUN_SAVE_VERSION` needs a migrator in `src/game/save/migrate.ts` and a fixture test. The meta profile (Crown Points, mastery, unlocks, settings) lives in store `meta` under key `current` (`META_SAVE_VERSION = 1`), is written when a run ends (before the run save is cleared) and is never deleted. Nomad's free relocation is the `freeMove` command (a per-year allowance from the king's data, counted in `freeMovesUsed`; `freeMoveIllegal` is shared with the planning UI). G3/G4 tests: `fullRun.test.ts` (9 real runs), `src/platform/resumeIntegration.test.ts` (reload matrix; it lives in `platform/` because `src/game` cannot import it).
- **Logic ↔ UI:** render/UI/scenes only read state and send intents through the typed `EventBus` (`src/core/events.ts`). Scenes launched with `scene.launch` start next frame — pass initial state in launch data, don't rely on events emitted in `create`.
- **Phaser scene instances are reused** across restarts: reset per-game fields at the top of `create()`.
- **Pixel art:** open colour/size metadata, no RGB or colour-count limit; keep legacy palette exports for compatibility — see `docs/ART_STYLE.md` (project owner requirement, 23/10/2026). Keep 32 px logical cells; one world atlas `sprites`, each side ≤ 4096. Use `pixelArt: true`, nearest sampling, integer sprite scale, pixel-snapped sprite/scroll display; the world camera alone may zoom by any factor (owner 08/11/2026: free zoom), its translation snapped to whole screen pixels (`snapView`), and the HUD never zooms; no AA/blur, sprite edge alpha 0/255 (separate declared shadows may use alpha 128). Registered exception: the CC0 Kenney Pixel UI Pack frames (panel/tooltip/button/card) overlay the generated ones via `src/render/uiKit.ts`; read frame size/slice/border through `uiFrameDef`, not `UI_FRAMES` directly. Sprites anchored at their feet `(0.5, 1)` and depth-sorted by that y; never rotate sprites (horizontal flip is fine). Sprites are referenced only by frame name (spec §11.4).
- **UI:** frames are nine-slices from the generated `ui` texture referenced by name (`UI_FRAMES` in `src/render/uiArt.ts`); size them in logical px with `createPanel` (`src/ui/theme.ts`), never with raw `Rectangle` backgrounds. Buttons come from `createButton`, tooltips from `Tooltip` (hover, or 400 ms long-press on touch), self-sizing boxes from `ContentBox`. Pure UI maths lives in `src/ui/hud/layout.ts` and `src/ui/menuLayout.ts` (tested). Every touch target is ≥ 44×44 logical px; recompute positions in `layout()` on resize; "desktop" = 1280×720, "mobile" = 375×812, `width ≥ 768` uses the desktop layout.
- **HUD text:** use `FONT_UI` — it must cover Vietnamese precomposed glyphs (Georgia does not). Player-facing text is Vietnamese; ids in code are English.

## Git workflow

`main` is release-only: it only receives a **release PR from `develop`**. Flow: feature branch → PR into `develop` → (when releasing) PR `develop` → `main`. Never open a feature PR against `main`, and never push directly to `main` or `develop`. Branch feature work from `develop`; after a release merge `develop` already contains `main`, so keep `develop` ahead of or equal to `main`.

## Phaser 4 notes

Official Phaser 4 agent skills live in `.claude/skills/*/SKILL.md` (also shipped in `node_modules/phaser/skills/`) — v3→v4 migration, cameras, input, tilemaps, sprites (NineSlice)… Read those instead of relying on Phaser 3 knowledge, and check signatures in `node_modules/phaser/types/phaser.d.ts`. Notable: `roundPixels` defaults false (set via `pixelArt: true`), FX/masks are now filters, `Geom.Point` → `Vector2`, `TileSprite` was rewritten (no texture cropping, supports atlas frames).

### Which Phaser skill to read

Always read `v3-to-v4-migration` before writing Phaser code from memory. Then by task:

| Priority | Skills | Use for |
|---|---|---|
| High | `scenes`, `sprites-and-images`, `game-setup-and-config`, `scale-and-responsive`, `input-keyboard-mouse-touch`, `text-and-bitmaptext`, `events-system` | Scenes, nine-slice UI, pixel-art config, desktop/mobile layout, cards and touch, HUD text, `EventBus` |
| Medium | `cameras`, `tweens`, `animations`, `loading-assets`, `graphics-and-shapes`, `render-textures`, `groups-and-containers`, `game-object-components`, `time-and-timers`, `v4-new-features`, `geometry-and-math` | Effects, unit animation, generated art/atlases, depth-sort/flip. Render/UI layers only |
| Low | `filters-and-postfx`, `particles`, `audio-and-sound`, `data-manager`, `actions-and-utilities` | Polish, audio (`src/audio` not created yet). Game state lives in `src/game`, not on game objects |
| Do not use for gameplay | `physics-arcade`, `physics-matter`, `tilemaps`, `curves-and-paths` | Battles are a custom deterministic sim (`SimClock`); the 5×5 board is not a tilemap. Phaser physics would break determinism |

## Workflow (superpowers)

New feature or behaviour change: `brainstorming` → `writing-plans` (spec in `docs/superpowers/specs/`, plan in `docs/superpowers/plans/`) → `test-driven-development` for `src/game`/`src/core`/`src/data` → `verification-before-completion` (the lint/typecheck/test/build command above) → `requesting-code-review` / `finishing-a-development-branch`. Bugs: `systematic-debugging` first.

## Dev server gotcha (Windows)

Vite's watcher can read a file before the write finishes and serve stale code; `vite.config.ts` sets `server.watch.awaitWriteFinish`. If the browser still shows old behaviour, restart `npm run dev`. Note the served module is transformed (`0.5` → `.5`), so don't grep it for exact literals.
